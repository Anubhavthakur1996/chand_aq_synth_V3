# Cyclical time encoding and a reduced training budget for DoppelGANger air-quality data (Chandigarh)

Code for a study that builds on Morales-Garcia et al. (2025), *Exploiting synthetic data generation to
enhance pollution prediction* (Applied Soft Computing 175, 113076) and its released code
(github.com/JuMoGar/synthetic_pollution_data_ua_upct_uca).  Like that work, it uses the Gretel
`timeseries_dgan` implementation of DoppelGANger (PyTorch).  Please cite and respect the licence of the
original repository.

No results are included here: the numbers from the earlier three-tier version of this repo were produced
with a different design and are kept, unchanged, under `archive/old_3tier_run/`.

## What is compared

Two changes to the base paper's setup, each measured on its own and together
(Base = the base paper's pollutants + weather. For Chandigarh this means NO and NO2 but **not** the station's NOx
column, which is unusable - see "NOx" in `CHANGES.md`; Bilbao keeps its valid NOx):

| Arm | Features | Training epochs |
|---|---|---|
| `a1_base_long`  | Base                         | 100,000 (base paper) |
| `a2_time_long`  | Base + cyclical hour/day-of-week | 100,000 |
| `a3_base_short` | Base                         | tuned short budget |
| `a4_time_short` | Base + cyclical hour/day-of-week | tuned short budget |

* Chandigarh (Sector 22, OpenAQ): all four arms, 5 seeds each.
* Bilbao (the base paper's data, vehicle and 8-hour columns removed so it matches Chandigarh):
  `a1` and `a4` only, as a second dataset.
* The short budget is chosen once, on validation data and on the Base arm only (`main.py tune`).

## How to run

```
pip install -r requirements.txt
pip install --no-deps gretel-synthetics==0.20.0     # must be installed WITHOUT its dependencies
python tests/test_windows.py        # unit tests of the windowing code
python tests/smoke_test.py          # whole pipeline with a stand-in generator (no GAN, ~2 min)
python main.py prep                 # cleaning; writes results/<dataset>/data_report.json
python main.py repro                # does the same seed give identical output on your machine?
python main.py tune                 # picks the short epoch budget -> results/chosen_epochs.json
python main.py run                  # Chandigarh, 4 arms x 5 seeds (resumable; skips finished runs)
python main.py run --dataset bilbao
python main.py summarize            # results/<dataset>/summary.txt, summary.csv, all_runs.csv
# replication check vs the base paper (after the Bilbao a1 runs; point to the base repo's synthetic CSV):
python main.py replicate --base-synth "<base repo>/3. AI models/1. Real vs Synth vs RealSynth/datasets/synth/60_Bilbao_synth.csv"
```
`python main.py all` does everything in order.  Settings live in `config.py`.

## Method details (what the code actually does)

* **Data** - hourly grid in local time; gaps of at most 3 consecutive hours are linearly interpolated,
  remaining missing hours are dropped; consecutive hours form `segment`s and no window or lag sample ever
  crosses a gap.  Counts are written to `data_report.json`.
* **Split** - Chandigarh: first 336 rows train, next 336 rows validation (tuning and held-out fidelity),
  all later rows test.  Bilbao: base-paper protocol (last 24 h test).
* **GAN** - Gretel DGAN, full batch, learning rate 1e-4, `sample_len = max_sequence_len = 24`, feature
  scaling on, example scaling off.  Training windows are non-overlapping 24-h days inside segments.
* **Time features** - sin/cos of hour and of day-of-week in local time (Asia/Kolkata for Chandigarh).
  They are generated by the GAN like any other feature; generated pairs are projected back onto the unit
  circle afterwards, and the validity of the raw generated clock is reported.
* **Post-processing** - non-negative clipping and relative humidity <= 100.
  (Physical bounds therefore come from clipping plus feature scaling, not from the architecture.)
* **Fidelity** (shared columns, so arms are comparable) - range-normalised EMD, JS distance (base 2),
  mean |ACF difference| computed inside each synthetic day, Frobenius norm of the correlation difference;
  against training days and against held-out real days.
* **Memorisation check** - mean distance of synthetic days to their nearest real training day, divided by
  the same quantity for unseen real days (ratio below 1 = synthetic days hug the training days).
* **Utility** - Train-on-Synthetic-Test-on-Real with Random Forest and gradient boosting, predicting PM2.5
  one hour ahead from the previous 12 hours.  Primary predictor columns are identical for every arm.
  TRTR (train on real) gives the reference; URR = TSTR MAE / TRTR MAE.  Reported at several synthetic
  volumes.  A shuffled-rows synthetic control is included.  For time-encoded arms an additional
  all-columns evaluation is reported as secondary.
